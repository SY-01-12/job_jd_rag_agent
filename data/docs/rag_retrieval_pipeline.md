# RAG 检索增强生成知识文档


## 1. RAG 的定义

RAG 是 Retrieval-Augmented Generation，即检索增强生成。它的核心思想是：在大模型回答问题之前，先从外部知识库中检索与问题相关的文档片段，再把这些片段作为上下文交给大模型生成答案。RAG 解决的是大模型无法直接访问私有知识、知识可能过时、容易幻觉、缺少引用来源等问题。

在企业应用和岗位分析 Agent 中，RAG 非常重要。大模型本身不一定知道本地文档里的岗位要求、学习路线、项目说明和内部知识。通过 RAG，系统可以把这些资料整理成知识库，并在用户提问时检索相关片段，保证回答更贴近资料。

在实际项目中，不能只背概念，而要能说明它在系统流程中的位置。一个可讲清楚的回答通常包括三点：它是什么、解决什么问题、如何在项目中落地。对于 AI Agent 应用开发实习，面试官更关注候选人是否理解工具调用、RAG 检索、向量库、Prompt 约束和接口化服务之间的关系，而不是只会说某个框架名称。


## 2. RAG 的离线阶段

RAG 通常分为离线阶段和在线阶段。离线阶段也叫索引阶段，主要包括文档收集、文档清洗、文档加载、文本切块、Embedding 向量化和向量库存储。文档加载是使用 Document Loader 把文件转成 Document 对象。文本切块是把长文档拆成多个 chunk。Embedding 向量化是把每个 chunk 转成向量。向量库存储是把 chunk、向量和 metadata 存入 Chroma、FAISS、Milvus 等向量库。

在 LangChain 项目中，常见流程是：DirectoryLoader 或 TextLoader 加载文档，RecursiveCharacterTextSplitter 进行切块，OpenAIEmbeddings 或 BGE 生成向量，Chroma 负责持久化存储。

## 3. RAG 的在线阶段

在线阶段也叫检索与生成阶段。流程是：用户输入问题，系统对问题进行向量化，然后从向量库中检索 Top-K 个相关 chunk。接着把检索到的 chunk 拼接成 context，再构造 Prompt，把 context 和 question 一起交给大模型。模型必须基于上下文回答，并返回引用来源。

典型流程如下：用户问题 → Query Embedding → Retriever 检索 → Top-K chunk → Prompt 拼接 → LLM 生成 → 返回 answer 和 sources。

## 4. 文本切块的重要性

文本切块直接影响 RAG 的检索质量。如果 chunk 太大，一个 chunk 中会混入太多无关内容，检索回来后上下文噪声较多，模型回答可能不准确。如果 chunk 太小，语义不完整，可能把问题所需的信息切散，导致检索回来只有半句话，模型无法准确回答。

chunk_size 控制每个文本块的大小，chunk_overlap 控制相邻文本块之间的重叠部分。对于一般 Markdown 技术文档，可以从 chunk_size=300 到 800 开始测试，chunk_overlap 可以设置为 50 到 100。

## 5. Retriever 与 VectorStore 的区别

VectorStore 是向量存储组件，负责保存文本向量、原文 chunk 和 metadata。Retriever 是检索接口，负责根据用户问题从 VectorStore 中返回相关文档片段。简单说，VectorStore 是存储层，Retriever 是检索层。

例如 Chroma 是向量数据库，可以存储向量和 metadata。调用 db.as_retriever(search_kwargs={"k": 3}) 后，就得到一个 Retriever。Retriever 接收 query，返回 Document 列表。每个 Document 包含 page_content 和 metadata。metadata 通常包含 source，用于返回引用来源。

## 6. Top-K 与相关性问题

Top-K 表示每次检索返回最相关的 K 个片段。K 太小可能漏掉答案，K 太大可能引入无关内容。对于只有几篇文档的小知识库，设置 k=3 可能会把弱相关文档也返回，因为系统会强行返回 3 个结果。此时可以设置 k=1 或 k=2，或者使用 similarity_search_with_score 查看分数，并设置阈值过滤低相关结果。

## 7. RAG Prompt 的设计

RAG Prompt 应该明确限制模型只能基于上下文回答。一个基础模板是：你是一个知识库问答助手。请只根据给定上下文回答问题。如果上下文中没有答案，请回答“资料中未提供相关信息”。不要编造上下文外的内容。

这种 Prompt 可以减少模型自由发挥，降低幻觉风险。特别是当用户问知识库没有的信息，例如“DeepSpeed ZeRO-3 是什么”，如果知识库没有相关内容，系统应该回答“资料中未提供相关信息”，而不是凭模型参数知识乱答。

## 8. RAG 为什么还会失败

RAG 并不是万能的。常见失败原因包括：文档本身没有答案、文档切块不合理、Embedding 模型效果不好、检索 Top-K 设置不合适、召回结果噪声过多、Prompt 约束不足、模型没有严格基于上下文回答。

排查时可以按顺序检查：知识库里是否真的有答案；检索结果是否命中正确 chunk；chunk 是否完整；Top-K 是否合理；Prompt 是否要求只基于上下文回答；是否需要 BM25 或 Reranker 优化。
