# 检索模型与向量库知识文档


## 1. 为什么 RAG 需要检索模块

RAG 的效果很大程度取决于检索质量。如果检索不到正确内容，大模型后面再强也只能基于错误或缺失的上下文回答。检索模块的目标是从知识库中找到和用户问题最相关的文档片段。常见检索技术包括 BM25、BGE、FAISS、Chroma 和 Reranker。

BM25 负责关键词检索，BGE 负责语义向量检索，FAISS 和 Chroma 负责向量存储和相似度搜索，Reranker 负责对初步召回结果进行重排序。真实项目中通常不会只依赖一种检索方式，而是组合使用。

## 2. BM25 的作用

BM25 是经典关键词检索算法。它根据 query 中的词和文档中词的匹配程度计算相关性分数。它考虑词频、逆文档频率和文档长度归一化。简单理解，BM25 适合找字面上匹配的内容。

BM25 的优势是对精确词非常敏感。例如 API 名称、函数名、错误码、配置项、模型名、文件名、产品编号、专业术语等。用户问“FastAPI Depends 是什么”“docker-compose.yml 怎么写”“text-embedding-v3 报错”，BM25 往往能直接命中文档中的关键词。

## 3. BGE 与 Embedding 的作用

BGE 是常用文本向量模型系列。Embedding 的作用是把文本转成向量，使语义相近的文本在向量空间中距离更近。BGE 适合自然语言问答、语义搜索和知识库检索。

例如用户问“怎么让大模型基于资料回答”，文档写“RAG 可以通过检索外部知识减少幻觉”，虽然字面不完全一致，但语义接近，BGE 更容易召回相关片段。BGE 的缺点是可能误召回语义上看似接近但事实上不相关的内容，也可能忽略精确术语。

## 4. BM25 和 BGE 的区别

BM25 看关键词匹配，BGE 看语义相似。BM25 不需要模型推理，速度快，成本低，适合精确词。BGE 需要 Embedding 模型，把 query 和文档都转成向量，适合同义表达和自然语言问题。

一句话总结：BM25 找字面相关，BGE 找语义相关。RAG 项目中，BM25 能防止精确术语丢失，BGE 能解决表达不一致问题。

## 5. FAISS 的作用

FAISS 是一个高性能向量检索库，适合本地向量相似度搜索。它可以保存向量索引，并快速查找最相似的向量。FAISS 更像底层向量检索库，适合本地 RAG 原型和中小规模检索。

FAISS 的优点是速度快、依赖轻、适合离线实验。缺点是元数据管理需要更多手动处理，不如一些向量数据库方便。

## 6. Chroma 的作用

Chroma 是面向 AI 应用的向量数据库，常用于 LangChain RAG 项目。它可以存储文本、向量和 metadata，支持持久化，也可以很方便地通过 as_retriever 转成 Retriever。

Chroma 对初学者更友好。使用 Chroma.from_documents 可以把 Document 列表写入向量库。后续使用 Chroma(persist_directory=..., embedding_function=...) 可以加载已有向量库。

## 7. Reranker 的作用

Reranker 是重排序模型，放在 BM25 或向量检索之后。BM25 和 BGE 的目标是召回一批可能相关的候选文档，Reranker 的目标是从候选文档中更精确地判断哪些最相关。

Embedding 检索通常把 query 和文档分别编码成向量，然后计算相似度，速度快但精度有限。Reranker 通常把 query 和文档成对输入模型，判断相关性更准确，但速度更慢。因此 Reranker 不适合对全库文档使用，而适合对 Top-N 候选做精排。

## 8. 混合检索流程

一个典型混合检索流程是：用户 query 输入后，BM25 召回 Top-K 文档，BGE 向量检索召回 Top-K 文档，两路结果合并去重，再用 Reranker 重排序，最后选择 Top-N 片段交给大模型。

这种流程比单一路径更稳，因为它同时保留关键词匹配和语义匹配的能力。对于企业知识库、技术文档和岗位分析系统，混合检索通常比单独向量检索更可靠。
