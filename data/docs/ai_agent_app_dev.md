# AI Agent 应用开发知识文档


## 1. AI Agent 的基本定义

AI Agent 是一种基于大语言模型的任务执行系统。普通聊天机器人主要负责根据用户输入生成文本回答，而 AI Agent 不只停留在文本生成层面。它通常具备任务理解、工具调用、流程控制、外部信息访问、结果整合和多轮上下文管理等能力。换句话说，AI Agent 的核心不是“会聊天”，而是“能借助工具完成任务”。

在应用开发场景中，AI Agent 往往由大模型、提示词、工具、任务调度逻辑、记忆模块、知识库、外部 API 和服务接口组成。大模型负责理解用户意图和生成自然语言；工具负责提供模型本身不具备的能力，例如计算、文件读取、数据库查询、搜索、知识库检索、HTTP 请求等；调度逻辑负责判断当前用户问题应该走哪个工具或流程；知识库负责提供私有或领域知识；服务接口负责让前端或其他系统调用 Agent 能力。

在实际项目中，不能只背概念，而要能说明它在系统流程中的位置。一个可讲清楚的回答通常包括三点：它是什么、解决什么问题、如何在项目中落地。对于 AI Agent 应用开发实习，面试官更关注候选人是否理解工具调用、RAG 检索、向量库、Prompt 约束和接口化服务之间的关系，而不是只会说某个框架名称。


## 2. AI Agent 与普通 Chatbot 的区别

普通 Chatbot 的典型流程是：用户输入问题，模型基于自身参数知识直接生成回答。它可以回答通用问题，但不一定能访问实时数据，也不能主动执行操作。AI Agent 的典型流程是：用户输入任务，模型先判断任务类型，再决定是否需要调用工具，然后根据工具返回结果继续推理或生成最终答案。

例如，用户问“23 * 17 等于多少”，普通 Chatbot 可能直接猜测答案，而 Agent 应该调用 calculator 工具计算。用户问“请读取 data/files/jd_agent_intern.txt 的内容”，普通 Chatbot 不能访问本地文件，而 Agent 可以调用 read_file 工具读取。用户问“RAG 的核心流程是什么”，Agent 可以调用知识库检索工具，从本地文档中检索相关片段，再基于上下文生成回答。

## 3. AI Agent 的核心能力

AI Agent 常见核心能力包括意图识别、工具调用、任务规划、记忆管理和外部知识使用。意图识别用于判断用户是要计算、读取文件、提取关键词、查询知识库，还是普通聊天。工具调用用于让 Agent 调用 calculator、read_file、extract_keywords、rag_search 等外部能力。任务规划用于把复杂任务拆成多个步骤，例如岗位分析任务可以拆成 JD 读取、技术关键词提取、能力差距分析、学习路线生成和简历优化建议。

记忆管理用于在多轮对话中保留最近上下文。例如用户前面说“我学完 Python 和 FastAPI”，后面问“下一步学什么”，系统应该知道用户已有基础。外部知识使用通常通过 RAG 实现，因为大模型自身不知道项目里的私有文档、岗位 JD、公司内部规范和学习材料。

## 4. Tool Calling 的含义

Tool Calling 是指模型根据用户问题选择一个外部函数或工具，并生成该工具所需的参数。程序接收到模型输出的工具名和参数后，执行工具，再把工具结果返回给模型或直接返回给用户。工具调用不是让模型自己真的执行文件读取或数学计算，而是模型负责“选择工具和生成参数”，实际执行仍由程序完成。

在岗位 JD 分析 Agent 中，常见工具包括 calculator、read_file、extract_keywords 和 rag_search。calculator 用于数学表达式计算；read_file 用于读取本地岗位文件；extract_keywords 用于从岗位描述中提取技术关键词；rag_search 用于从知识库中检索并回答技术概念问题。

## 5. 大模型工具选择的 JSON 输出

为了让工具调用稳定，通常要求模型输出固定 JSON。例如 need_tool 表示是否需要工具，tool_name 表示工具名，arguments 表示工具参数。计算问题可以输出 calculator 和 expression；文件读取问题可以输出 read_file 和 file_path；知识库问题可以输出 rag_search 和 question；普通闲聊可以输出 none 和空参数。

结构化输出的好处是程序可以用 json.loads 解析结果，避免自然语言回答难以处理。为了减少错误，Prompt 中应该明确要求“只输出 JSON，不要输出 Markdown，不要输出解释”。如果模型输出 ```json 代码块，程序也要做清理。

## 6. Agent Runner 的职责

Agent Runner 是项目的总控模块。它不负责具体工具实现，也不负责向量库构建，而是负责调度流程。用户输入问题后，Agent Runner 调用 tool_decision 判断工具类型，然后根据 tool_name 进入不同分支。如果是 calculator，就调用 calculator_tool；如果是 read_file，就调用 file_tool；如果是 extract_keywords，就调用 keyword_tool；如果是 rag_search，就调用 rag_chain；如果是 none，就直接调用大模型回答。

Agent Runner 应该返回统一格式，例如 answer、tool_used 和 sources。统一输出格式方便命令行展示，也方便后续接入 FastAPI 接口。

## 7. 岗位 JD 分析 Agent 的应用场景

岗位 JD 分析 Agent 的目标是帮助实习求职者理解岗位要求。用户可以输入一段岗位描述，系统自动提取技能要求，例如 Python、FastAPI、LangChain、RAG、向量数据库、Dify、Coze、Docker、Linux、Git 等。系统还可以基于知识库解释每项技术的作用，并给出学习顺序。

这种项目适合作为 AI Agent 应用开发实习的简历项目，因为它覆盖了真实岗位中常见能力：大模型调用、工具判断、结构化输出、文件读取、关键词提取、RAG 问答、引用来源返回和命令行交互。后续还可以接入 FastAPI，提供 /agent/chat、/rag/chat 和 /upload/jd 等接口。
